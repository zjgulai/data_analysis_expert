# 指标体系编排台 — 深度优化方案（MECE）

> 节点深化系列第 04 篇。统一 11 节模板。指标体系把单个可信指标（03）编排成"可分解、可归因、可对齐战略"的树——它是把"指标数值"翻译成"管理决策"的关键一跳。

## 1. 节点定位与边界（MECE 区分）

**一句话定义**：指标体系是用**因果/构成关系**把指标组织成树（或 DAG），让任意一个顶层结果指标都能 **MECE 地分解到可被某个 owner 拉动的操作杆**，并支持"指标异动→沿树定位驱动因子"的归因。

边界（承接 03 的口诀"04 造砖、06 砌墙"）：

| 关注点 | 指标工程 04（造砖）| 指标体系 06（砌墙，本篇）|
|---|---|---|
| 对象 | 单指标本身 | 指标之间的**关系** |
| 产物 | 可信原子/派生指标 | 树/权重/归因/北极星分解 |
| 问题 | "这个数怎么算、可信吗" | "这个数由谁驱动、动了多少、谁来管" |

范围内：北极星与顶层结构、树形关系类型、权重与贡献度、归因路径、MECE 校验、体系健康度、业务对齐与 owner 映射。
范围外：单指标定义与字段映射（→03）、口径检索（→05）、标签判定（→02）。

## 2. 现状精确画像（实测证据）

| 维度 | 实测 | 判断 |
|---|---|---|
| 树规模 | `kpi_tree` **172** 边（CONTAINS:33 / DECOMPOSED_TO:139）| 结构骨架完整，覆盖 L0→L3 |
| 层级分布 | L0:6 / L1:8 / L2:25 / L3:139 | 金字塔形态合理 |
| **权重** | `kpi_tree.weight` **全为 NULL** | **无定量归因能力**——树只能"看结构"不能"算贡献" |
| 关系类型 | 仅 `CONTAINS`（构成）/ `DECOMPOSED_TO`（分解）| 缺 `DRIVES`（因果驱动）/ `CORRELATES`（相关），无法表达"驱动而非构成" |
| 北极星 | `SCM-MECE-L0-001 供应链综合效能指数`（composite，依赖 5 个子项）已存在 | **北极星已定义**，但子项权重与认证缺失 |
| MECE 校验 | 无校验机制 | 子项是否穷尽父项、是否互斥，无人验证 |
| 健康度 | 无体系级健康分 | 体系"完成度/可信度"不可见 |
| UI 能力 | `KpiTreePanel`（`main.tsx:4617`）：Mind Map / Object Graph / Table 三视图 + 一跳聚焦 + Inspector + Drawer | **可视化是全平台最成熟的**，但展示的是"无权重的结构"——引擎弱于外壳 |
| 方法论底座 | `02_Momcozy_KPI体系设计.md` 已有"成本满意度 50% + 履约满意度 50% = 综合供应链满意度" | 权重在**文档里有、系统里空**——只需回填 |

**结论**：指标体系"有树、有图、无算力"。可视化外壳已领先，缺的是**权重 + 因果关系 + MECE 校验 + 归因**这套"让树会算账"的引擎。这正是用户"不专业、不完整"的精确所指。

## 3. 标杆方法论（MECE 驱动树 + 北极星）

**3.1 驱动树的 MECE 双门禁**（来源见 00-index）：算术闭合只能证明子项在当前口径下覆盖父指标，不能证明子项互斥；必须先验证每个事实/费用只归属一个子项，再验证覆盖完整且残差闭合，二者同时通过才可判定为 MECE。例：
```text
供应链成本率 = (头程 + 仓储 + 尾程 + 逆向 + 直邮成本) / GMV
→ 先证明费用归属互斥，再证明每项独立可测且加总=父项 ⇒ MECE 成立
```
**3.2 北极星分层**：北极星 → 3–5 个驱动指标 → 子驱动 → 操作输入，每层每节点有**具名 owner**，把"公司级结果"一路连到"团队能拉的杆"。
**3.3 语义层赋能**：度量树经语义层（03）落地，才能从"看板"变"可执行 BI"——树的每个节点都是认证指标，点开即可下钻真实数据。

对照本平台：北极星（SCEI）已有，但"每层 owner + 权重 + 算术闭合校验"缺失。本篇即补这三件事。

## 4. 目标能力 MECE 拆解

指标体系拆为 7 个互斥且穷尽的能力域：

### A. 北极星与顶层结构（North Star）
确认 `SCEI` 为唯一北极星，固化其 5 维一级驱动（成本效率 / 可售保障 / 库存资金效率 / 履约体验 / 数据可信），每维定 owner 与目标值。避免"多北极星"导致的目标稀释。

### B. 树形关系类型（Relation Semantics）
扩展关系语义（当前仅 2 种）：
- `CONTAINS`：构成（父=子之并集，结构性）。
- `DECOMPOSED_TO`：算术分解（父=f(子)，可算）。
- 新增 `DRIVES`：因果驱动（子↑→父↑/↓，非构成，带方向与时滞）。
- 新增 `CORRELATES`：相关但非因果（标注以防误归因）。
关系类型决定能否做"加权归因"——只有可算关系（DECOMPOSED_TO/DRIVES）参与定量分解。

### C. 权重与贡献度（Weight & Contribution）
回填 `weight`（先用方法论文档里的业务权重，如成本/履约 50:50），并区分两种贡献：
- **结构权重**（static weight，规划期设定）。
- **动态贡献度**（contribution，本期实际：某子项变化对父项变化的解释占比）。
贡献度让"为什么 SCEI 跌了"有定量答案。

### D. 归因路径（Attribution Path）
当顶层指标异动，沿可算关系自顶向下逐层分解，输出"贡献度排序的驱动因子链"（如 SCEI↓ ← 履约体验↓ ← 未发货率↑ ← 某区域审核积压）。这是洞察故事线（05）的"归因"环节的供给侧。

### E. MECE 校验（MECE Validation）
机器可跑的体系校验：
- **穷尽性**：子节点（经 DECOMPOSED_TO）加总/加权是否≈父节点（算术闭合，允许残差阈值）。
- **互斥性**：同层子节点口径是否重叠（借 03 的口径包含/排除清单比对）。
- **覆盖率**：每个 L0/L1 是否都已分解到可执行 L3。
- **孤儿/悬空**：无父或无认证子的节点告警。

### F. 体系健康度与认证（Health & Certification）
体系级健康分 = f(节点认证率、血缘置信度、权重完整度、MECE 通过率、数据新鲜度)。在 KpiTreePanel 上用颜色标注每节点认证/健康状态（外壳已支持，只需喂数据）。

### G. 业务对齐与 owner 映射（Alignment）
每个节点绑定 owner 与对应**角色工作台**（计划/采购/仓库/物流/成本/管理层），把北极星分解结果直接路由到"谁该看、谁该管"，与既有 R2 角色作战工作台打通。

> MECE 自检：A 定顶 / B 定关系 / C 定权重 / D 做归因 / E 验 MECE / F 评健康 / G 对齐人——七域无重叠，并集覆盖"建体系→让体系会算→保体系可信→把体系连到人"。

## 5. 治理方法与 SOP

```text
确认北极星(A)
 → 自顶向下分解(B：选对关系类型，优先可算的算术分解)
 → 回填权重(C：业务权重先行，统计权重回测校准)
 → MECE 校验(E：算术闭合 + 口径互斥 + 覆盖率)
 → 绑定 owner 与角色台(G)
 → 体系认证(F：节点认证率/血缘达标 → 体系健康分)
 → 上线归因(D：异动可下钻驱动因子)
 → 周期复盘(动态贡献度回流，校准权重)
```

## 6. 自动化与 AIP 闭环

| 环节 | 指标体系角色 |
|---|---|
| 发现 | 北极星/一级驱动破阈值 → 触发场景 |
| 解释 | **归因路径（D）自动产出驱动因子链** → 喂洞察故事线（05）的"为什么" |
| 推荐 | 驱动因子定位到操作杆（G 的 owner）→ 推荐动作有的放矢 |
| 复盘 | 动作后看驱动因子贡献度回落，验证归因正确性 |

AIP 价值点：**归因自动化**是从"BI 看板"跃迁到"AIP 决策系统"的分水岭——AI 不只报"SCEI 跌了"，而是沿认证指标树给出"跌在哪、谁负责、跌了多少"，全程可审计。

## 11. 风险与缓解

| 风险 | 缓解 |
|---|---|
| 权重拍脑袋 | C 先用方法论文档业务权重，再以历史数据回测校准，留依据 |
| 把"相关"当"因果"误归因 | B 用 CORRELATES 显式区分，DRIVES 须有方向+时滞+证据 |
| MECE 算术不闭合（残差大）| E 设残差阈值，超阈值标注"待补口径"，不强行平账 |
| 体系庞大 → 维护成本 | 先治 L0–L2 主干（少而关键），L3 渐进 |
| 健康分被当 KPI 刷分 | F 健康分只做体系可信度透明化，不与个人考核绑定 |
