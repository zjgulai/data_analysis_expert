# 洞察故事线 — 深度优化方案（履约看板页面级）

> 节点深化系列第 05 篇。统一 11 节模板。**范围已按用户确认收敛**：本篇只做"供应链履约看板（F1）"的**页面级洞察故事线**——即把看板从"一堆图表"升级为"会讲因果、能落到动作"的页面叙事，而非全局独立叙事层。

## 1. 节点定位与边界（MECE 区分）

**一句话定义**：页面级洞察故事线，是在单个看板页面内，用**结论先行 + 因果叙事**的结构，把"指标卡/图表"组织成"现象→口径→异常→归因→建议"的连贯故事，让看的人不只"看到数"，而是"看懂事、知道做什么"。

边界切分（与相邻概念区分，防止越界做成"另一个决策闭环"）：

| 概念 | 范围 | 归属 |
|---|---|---|
| **页面级洞察故事线（本篇）** | 履约看板**单页内**的叙事结构与洞察单元 | F1 履约看板 |
| 全局决策闭环 | 跨页/跨对象的审批、动作执行、复盘台账 | 决策闭环 10 / 06 |
| 指标归因 | 指标体系树上的驱动因子分解 | 指标体系 06（本篇消费其产出）|
| 指标口径 | 单指标的定义与字段 | 指标工程 03（本篇引用）|

范围内：页面叙事结构、洞察单元规格、证据链、页面级"异常→归因→建议"串接、决策叠加层、下钻叙事、故事线治理与新鲜度。
范围外：动作的审批与执行（→10）、跨系统 write-back（受控边界禁止）、指标体系本身的权重归因引擎（→06）。

## 2. 现状精确画像（实测证据）

履约看板（`public/fulfillment-dashboard/`，经主站 `FulfillmentDashboardPanel` 以 iframe 接入）实测：

| 维度 | 实测 | 判断 |
|---|---|---|
| 形态 | 静态前端（`index.html`+`app.js`+`styles.css`）+ 4 个数据契约 CSV + 4 篇文档 | 知识原型，**不接生产库**（边界正确）|
| 页头标语 | "指标体系先行，口径对齐后进入履约洞察故事线" | **"故事线"是宣称的目标，但页面实现仍是指标卡/图表罗列** |
| 主题模块 | 履约时效 SLA、未发货预警（7/10/15 天分层）、缺货分析（订单/库存/预测三分法）、审核效能（系统 vs 人工双口径）、跨区矩阵、明细下钻 | 主题划分专业、已有重要业务决策沉淀 |
| 已确认业务规则 | 未发货预警保留独立模块；缺货三分法；审核效能双口径；平均发货成本暂不入核心 KPI 与故事线 | 规则清晰，是故事线的好素材 |
| 决策叠加 | 存在 `fulfillment_metric_decision_overlay_20260625.csv` | **决策叠加雏形已有，但未结构化为"洞察→建议"单元** |
| 证据/口径 | `metric_dictionary` CSV + `source_table_contract` CSV + `sql-bi-logic` 文档 | 口径与数据契约齐备，**故事线可挂证据链的"锚点"已就绪** |
| 叙事结构 | 无 SCQA/金字塔结构；无"结论先行"；无页面级"为什么+建议" | **缺的就是"故事"本身**——有事实素材，无叙事骨架 |

**结论**：履约看板"素材专业、骨架缺位"。口径、数据契约、业务规则、决策叠加 CSV 都在，但页面仍是"展示型看板"而非"叙事型洞察"。优化 = **给已有素材装上"结论先行 + 因果链 + 建议"的故事骨架**，且全部可在样例数据上跑通，预留真实数据绑定。

## 3. 标杆方法论（数据叙事）

**3.1 SCQA（Minto / 麦肯锡）**（来源见 00-index）：Situation（现状）→ Complication（异常/冲突）→ Question（要回答什么）→ Answer（结论与建议）。页面级落法：每个核心页面顶部用一句话给"结论 + 建议"，下面才是支撑图表。
**3.2 金字塔原理**：**结论先行**，再用 2–4 个支撑论点 + 数据展开。对抗"看板让人自己找结论"的通病。
**3.3 叙事弧**：Context → Complication → Climax/Insight → Resolution/Call-to-Action——天然匹配供应链"发现异常→归因→推荐动作"的闭环。

把三者合一为**履约页面故事线骨架**：
```text
[结论先行] 一句话：当前履约健康度 + 最该管的 1 件事
  ↓
[Situation] 现状口径：核心指标 + 对比基准（同比/环比/目标）
  ↓
[Complication] 异常：哪些指标/分群破阈值（挂标签 02）
  ↓
[Insight/归因] 为什么：沿指标体系 06 的驱动因子链 + 责任域
  ↓
[Answer/Action] 建议：决策叠加给出"谁、做什么、SLA"（止于建议，不执行）
```

## 4. 目标能力 MECE 拆解

页面级洞察故事线拆为 7 个互斥且穷尽的能力域：

### A. 页面叙事结构（Narrative Spine）
每个核心页面有固定故事骨架：**结论条（结论先行）→ 现状 → 异常 → 归因 → 建议**。模板化，保证每页"读得懂、有结论"。

### B. 洞察单元规格（Insight Unit）
最小洞察单元的统一结构：现象（指标+数值）/ 口径引用（→03）/ 对比基准（目标/同比/环比）/ 异常判定（阈值/标签）/ 归因（驱动因子）/ 建议（动作+owner+SLA）/ 置信度。让"洞察"成为可复用、可治理的对象而非自由文本。

### C. 证据链与可追溯（Evidence Chain）
每条洞察可一键回到：认证指标口径（03）、命中标签（02）、关联对象实例（01）、源表数据契约（已有 CSV）。落实页头承诺的"口径对齐后才进入故事线"。

### D. 异常→归因→建议串接（Storyline Flow）
把当前并列的主题（未发货 / 缺货 / 审核效能）各自串成一条因果链。例：
```text
未发货率↑(现象) → 7/10/15 天分层定位积压段(异常)
→ 责任域归因：审核积压? 缺货? 物流揽收?(归因)
→ 建议：对 X 责任域发起 Y 评审(建议，止于 suggestion)
```

### E. 决策叠加层（Decision Overlay）
把已有 `fulfillment_metric_decision_overlay` CSV 结构化为"指标卡→建议动作"的叠加：每个核心指标卡可挂 0..N 条建议（含 owner/SLA/风险等级），与决策闭环 10 衔接但**页面内只展示建议**。

### F. 交互与下钻叙事（Guided Drill）
把"缺货三分法""审核双口径"做成**引导式下钻路径**：从页面结论 → 分群（订单/库存/预测缺货；系统/人工审核）→ SKU/审核人明细，每步都带"这一层在回答什么"的叙事提示，而非让用户自己点。

### G. 故事线治理与新鲜度（Governance & Freshness）
故事线模板版本、口径对齐前置门禁（口径未认证则该洞察标"口径待对齐"）、数据契约绑定、静态原型边界声明、数据新鲜度标注（看板按天刷新）。

> MECE 自检：A 定骨架 / B 定单元 / C 接证据 / D 串因果 / E 挂建议 / F 引导下钻 / G 管治理——七域无重叠，并集覆盖"把图表变成可信、可追溯、能落到建议的页面故事"。

## 5. 治理方法与 SOP

```text
指标体系先行(确认本页核心指标已在 06 树上、03 口径已认证)
 → 定义页面故事骨架(A：结论先行模板)
 → 拆洞察单元(B：每个核心指标一个单元)
 → 挂证据链(C：口径/标签/对象/数据契约)
 → 串因果链(D：现象→异常→归因→建议)
 → 挂决策叠加(E：建议+owner+SLA)
 → 评审(口径对齐 + 业务规则一致)
 → 上线(样例数据跑通，预留真实数据绑定)
 → 复盘(建议被采纳/驳回回流，校准故事线)
```

## 6. 自动化与 AIP 闭环（页面级）

| 闭环环节 | 页面故事线角色 | 边界 |
|---|---|---|
| 发现 | 指标卡破阈值/标签命中即"异常高亮" | 只读样例/数据契约 |
| 解释 | 洞察单元自动展开"归因 + 证据链" | 可追溯 |
| 推荐 | 决策叠加给出建议动作卡 | **仅建议，页面不执行** |
| 审批执行 | 跳转决策闭环 10 处理 | 受 suggestion_review_replay 约束 |
| 复盘 | 建议采纳结果回流页面，标注"已处理/驳回" | 学习闭环 |

AIP 落位：页面故事线是 AIP 闭环的**"最后一公里展示层"**——它让"发现→解释→推荐"在业务人员每天看的页面上自然发生，而把"审批→执行→复盘"交给受控的决策闭环，严守"不写回生产"的边界。

| 新增/扩展 | 关键字段（设计）| 说明 |
|---|---|---|
| `storyline_template`（新，JSON）| page_id, spine(结论/现状/异常/归因/建议), version | A |
| `insight_unit`（新，CSV/JSON）| id, page_id, metric_ref, baseline, threshold_or_tag, attribution_ref, suggestion_ref, confidence, evidence_refs | B/C |
| `decision_overlay`（结构化现有 CSV）| metric_card_id, suggestion, owner, sla, risk_level | E |
| `drill_path`（新）| page_id, step, question, dimension, target | F |
| `storyline_freshness`（新）| page_id, caliber_aligned, last_refresh, boundary_note | G |

## 9. 验收标准与度量

| 维度 | 当前 | 目标（首阶段）|
|---|---|---|
| 有故事骨架的核心页面 | 0 | ≥ 3（未发货/缺货/审核效能）|
| 结论先行 | 无 | 每核心页顶部 1 句"结论+最该管的事" |
| 洞察单元可追溯口径 | 部分有 CSV | 每个洞察单元 100% 可回到认证口径/数据契约 |
| 决策叠加结构化 | CSV 雏形 | 核心指标卡 100% 可挂建议（owner/SLA）|
| 边界合规 | 合规 | 保持：不接生产库、建议止于 suggestion |

## 11. 风险与缓解

| 风险 | 缓解 |
|---|---|
| 故事线写成"硬编码叙事"脱离数据 | B/C 强制每条洞察绑定口径与数据契约；模板化生成而非手写结论 |
| 越界做成"另一个决策闭环" | 第 1 节边界表：页面内只到"建议"，执行交 10 |
| 口径未对齐就讲故事 → 误导 | G 口径对齐前置门禁，未认证口径标"待对齐"不进故事线 |
| 静态原型与真实数据脱节 | 增量以数据契约形式设计，预留真实数据绑定接口 |
| 叙事过度 → 信息过载 | 结论先行 + 每页聚焦"1 件最该管的事" |
